Phase 2: Authentication, User Panel & Admin Panel
This plan outlines the architecture and implementation steps for user authentication, the client dashboard, and the administrative control panel.

Architecture & Tech Stack Updates
Authentication: We will use JSON Web Tokens (JWT) via Flask-JWT-Extended to secure communication between the Next.js frontend and Flask backend.
State Management: React Context or lightweight state hooks in Next.js to manage the authenticated user session.
Routing: Next.js Route Groups (e.g., (auth), (user), (admin)) to separate the public website layout from the dashboard layouts.
Implementation Steps
1. Backend Authentication (Flask API)
Install Flask-JWT-Extended and Flask-Bcrypt (for password hashing).
Create POST /api/auth/register: Accepts user details, hashes the password, and creates a User record.
Create POST /api/auth/login: Verifies credentials and returns an access token and user role.
Create GET /api/auth/me: Protected route to return the current user's profile.
2. Frontend Authentication Pages
Create /register page matching the dark, cinematic theme.
Create /login page for returning clients and administrators.
Implement JWT storage (using localStorage or cookies for API requests).
3. User Panel (Client Dashboard)
Create a protected layout under src/app/(user)/layout.tsx (different from the public website layout).
Dashboard (/dashboard): Shows welcome message and upcoming reservations.
Reservation System (/dashboard/reserve): A comprehensive multi-step form to request a photography/cinematography package on a specific date.
My Reservations (/dashboard/reservations): A list of the user's past and upcoming reservations with real-time status badges (Pending, Confirmed, etc.).
4. Admin Panel
Create a protected layout under src/app/(admin)/layout.tsx with a professional sidebar navigation.
Admin Dashboard (/admin): Overview statistics (Total Users, Pending Reservations, Recent Contact Messages).
Reservations Manager (/admin/reservations): Table to view all reservations with the ability to Approve, Reject, or Cancel them.
Contact Messages (/admin/messages): Inbox to read and manage inquiries submitted from the public /contact page.
Backend Endpoints: Ensure these routes are protected in Flask with @jwt_required() and role-based checks (Admin only).
Open Questions
IMPORTANT

Phase 3: Front‑End Quality & Visual Upgrade
This plan audits the existing Next.js UI, enumerates current bugs, and outlines a roadmap for a high‑end visual redesign with modern animations.

1️⃣ Front‑End Bug Audit (Current Issues)
Page / Component	Symptom	Likely Cause	Impact
Navbar	Hamburger menu does not close on navigation; occasional overflow on small screens.	State not reset / missing aria-controls.	Mobile usability.
Contact Form	Validation messages appear in plain red text without contrast; form does not prevent double‑submit.	Custom validation styling missing; missing disabled state.	UX friction.
Portfolio / Stories Grid	Images stretch on certain viewport widths; grid gaps collapse on Safari.	Tailwind grid-cols not responsive; missing object‑fit.	Visual inconsistency.
Footer	Links lack focus outlines; screen‑reader navigation is poor.	No focus-visible styles; missing aria-labels.	Accessibility.
Responsive Layout	Some pages (e.g., /journal) cause horizontal scroll on tablets.	Fixed width containers (w-[800px]).	Poor mobile experience.
Dark Theme Contrast	Text on dark cards sometimes fails WCAG AA contrast (#d8c3a5 on #0f0f0f).	Color palette not tested.	Accessibility.
Next.js 14 App Router	Certain client components use server‑only APIs (fs) causing hydration errors.	Misplaced imports.	Console errors.
Image Loading	Large hero images load slowly; no lazy‑loading.	next/image not used.	Performance.
State Management	Multiple pages share duplicated useState logic for forms.	No shared hook.	Code duplication.
2️⃣ Visual Design Enhancements
Adopt a design system based on the provided dark cinematic aesthetic:
Primary palette: #0f0f0f (background), #d8c3a5 (accent), #f5f5f0 (text).
Typography: Playfair Display for headings, Inter for body.
Spacing: 8‑px baseline, rem units.
Replace static images with Next.js next/image for automatic optimization, lazy‑loading, and responsive sizing.
Introduce CSS custom properties for theme colors to simplify future brand tweaks.
Refactor the global layout to use Tailwind’s container utility with mx-auto for consistent max‑width across break‑points.
Add accessible focus rings (focus-visible) and ARIA labels on interactive elements (nav, buttons, forms).
Ensure WCAG AA contrast by adjusting text colors on dark cards (#e0e0e0 instead of #f5f5f0).
3️⃣ High‑End Animations & Interaction
Section	Animation Idea	Recommended Library / Technique
Page Transitions	Fade‑in + slide‑up when navigating between routes.	framer-motion with <AnimatePresence> in layout.tsx.
Navbar	Smooth slide‑down on scroll, animated hamburger → X morph.	framer-motion or CSS transition on transform.
Hero / Banner	Parallax scrolling with layered image & text, subtle zoom on scroll.	react-parallax or manual useViewportScroll + motion.div.
Portfolio Grid	Staggered fade‑in + scale on scroll, hover tilt effect.	framer-motion whileHover + whileInView.
Buttons / CTAs	Ripple effect + color shift on click.	Tailwind active: + custom @keyframes.
Form Interactions	Input label float animation, field shake on validation error.	CSS transition + conditional className.
Admin/User Dashboards	Chart fade‑in, table row slide‑in, notification toast slide.	recharts + framer-motion for entry.
Performance considerations:

Keep animation duration ≤ 300 ms for most UI actions.
Use GPU‑friendly properties (transform, opacity).
Leverage prefers-reduced-motion media query to disable heavy animations for accessibility.
